# Project instructions

## Start of every session

Before planning or modifying this project, read:
1. Codex.md - the user's specification.
2. QA.md - confirmed answers and unresolved questions.
3. app-context.md - current requirements, decisions, evidence, and progress.
4. Find all documents in ./build-docs.

## Keep project memory current

- If not present, create build-docs folder.
- Record relevant clarification questions and the user's answers in QA.md.
- Update app-context.md whenever meaningful progress is made or requirements, decisions, implementation status, or next steps change.
- Clearly distinguish confirmed user requirements from assumptions and proposals.
- Follow the latest explicit user instructions if older documentation conflicts, and reconcile these files accordingly.
- Do not mark work as implemented or verified unless it actually is.
- Preserve local-only processing and storage unless the user explicitly changes that requirement.
